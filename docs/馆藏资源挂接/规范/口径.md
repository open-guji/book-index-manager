## 二、实抽发现（与口径的差距，交 B 块处置，本块不改库）
1. **Book 层 resources 缺 `id`：6,308 条**（`types` 均为 `["image"]`，URL 多为 commons 文件）。`common.md` 写 `id` 必填。→ B 块「id」类问题，先列清单，不改。
2. **Book 层 `id` 常是一次性键**（`ia-hongloumeng-*`、`baidu-*`、`npm-rarebooks-1/2/3/4`、`tul-iiif-1/2` 等），不是站点 id。K6 只约束新写入；存量是否迁移由 B 块结论定。
3. **Work 层 `shidianguji-*`**（约三十种版本后缀）同为识典古籍，`types` 均为 `["text","image"]`，无 `group`。口径对新写入不要求补；存量是否合并 id 由 B 块定。
4. **`physical` 在 Book 层大量存在**（npm-rarebooks 17,534 条），符合 K4。
5. **group 前缀不统一**：内閣文庫 `naikaku-` 与站点 id `nat-archives-jp` 不同，已在 K7 注明，不当错误。
6. **Work 层 `resource_groups` 可含其他来源的组**（样例 5 的《六書通》Work 里 `kokusho` 与 `nlc-*` 组并存），属正常。
