## 一、本块目标与边界
目标：给全库已挂资源出一张体检表，并对每类问题给出「迁移／保留／删除」结论。　｜　不做：不改库（只读 book-index）；不迁移，迁移若需要另开块并经 Marlowe 批；不重做 #455 已处理的故宫 375 条。　｜　交付物：`体检表.tsv`、`体检结论.md`、`scripts/馆藏资源挂接/health_check.py`。

## 二、Schema／数据格式（完整）
`体检表.tsv`（每行一个问题实例）：
| 列 | 类型 | 取值 | 含义 |
|---|---|---|---|
| file | 文本 | 仓内路径 | 记录文件 |
| layer | 枚举 | Work／Book | 所在层 |
| res_index | 整数 | ≥0 | `resources[]` 下标 |
| site | 文本 | 站点 id | |
| url | 文本 | 可空 | |
| problem | 枚举 | dup（同 URL 重复）／layer（错层）／id（id 与口径不一致）／type（types 不合口径）／dead（链接坏）／group（group 缺失或矛盾） | |
| suggest | 枚举 | keep／fix／delete／migrate | |
| evidence | 文本 | 可空 | 判据或原始 HTTP 状态 |

## 三、程序架构
`health_check.py`：扫描 `Work/`、`Book/`（排除 `merged_into` 已并条），按口径.md 规则输出 dup／layer／id／type／group 五类；`dead` 类由链接抽检另跑（限速 ≥2 秒／次，按站点分层随机抽样，不全量）。复用 `scripts/馆藏资源挂接/stat_res.py` 的遍历方式。运行在云端会话，只读。
