## 一、目标
给 E 块各批次出**盲样抽检表**，判定匹配写入是否错挂，按期交给 Rhea 审；抽检结论只报，不写库、不合并。

## 二、分步（每步：输入 → 做法 → 验收）
| 步 | 做什么 | 输入 | 验收 |
|---|---|---|---|
| S1 领批 | 向 Rhea 领一份批次任务，登记：批次号、来源、预计写入条数、交付日期 | Rhea 的任务单（卡上） | 卡上有任务单链接；未收到单子不开工 |
| S2 抽样 | 按任务单规则抽样；固定随机种子并写进表头；样本数不低于口径要求（K10：正式库写入 ≥185 条、全对为下限；链接抽检 150 条 HTTP 200） | 该批 write_plan／匹配表（只读） | 样本数、种子、总体条数写在表头，可复算 |
| S3 盲判 | 只看站方题名、责任者、朝代、版本信息，**不看匹配表的结论与 work_id 来源**，逐条判 ok／错挂／存疑 | 站方原始记录（URL 抓取，≥2 秒／次） | 每条有判定与一句说明；存疑不计错，但单列 |
| S4 对账 | 盲判结果与匹配表逐条比对，算错挂率、下限，列出不一致条目 | S3 结果、匹配表 | 对账脚本输出附在表末；数字带命令或脚本路径 |
| S5 交付 | 出抽检表（格式同 Sylvie 样例：source／work_id／url／判定／说明）＋一行结论（通过／不通过／待核），发给 Rhea 审 | S4 结果 | 结论行写明样本数、错挂数、下限；没发现问题也回一行 |

## 三、交付物
- 每批一份 tsv：`项目进展/馆藏资源挂接/计划/写入-独立抽检-<批次>-Remy.tsv`
- 每批一行结论，写在 GUJI-335 卡上；不另写长报告。

## 四、不做什么
- 不改匹配表、不改判据、不替程序员修脚本；错挂只列出，不修。
- 不写 book-index 或 book-index-draft；写库前须先登记排班，由 Rhea 或 Marlowe 批。
- 不合并任何 PR；不做对外动作。
- 盲判时不与匹配者（Everett／Sol 等）讨论单条结论。
