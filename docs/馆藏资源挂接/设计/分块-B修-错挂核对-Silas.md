## 一、本块目标与边界
目标：对体检发现的「同题、作者互不相交、共用同一资源 url」的 605 个 url／1,372 条记录，到原站逐条核对该 url 到底是哪一本，**留对的一边、删错的一边**，判不了的记「存疑」不动。　｜　不做：不改 schema；不新建 Work／Book；不动「不同题名共用」的 2,038 个 url（四库册共用，合理）；13 个疑似重复 Work 转 Sabine 去重线；一方无作者的 60 个 url 先保留；不挂新资源。　｜　交付物：`核对表.tsv`（每 url 一行）、改库 PR（每 PR 附原站核对表）、`错挂核对报告.md`。

## 二、Schema／数据格式（完整）
输入：`项目进展/馆藏资源挂接/计划/dupx-同题异作者清单.tsv`（每行：url＋涉及的记录路径，制表符分隔）。重新生成方法：`scripts/馆藏资源挂接/health_check.py` 输出中 `problem=dupx` 且同题异作者（判据见体检结论 §二）。

`核对表.tsv`（每个 url 一行）：
| 列 | 类型 | 取值 | 含义 |
|---|---|---|---|
| url | 文本 | | 被共用的资源 url |
| site | 枚举 | commons／shidianguji／wikisource／archive-org | 来源分层 |
| record_paths | 文本 | 分号分隔 | 共用该 url 的记录文件 |
| page_title | 文本 | | 原站页面标题（取证） |
| page_author | 文本 | 可空 | 原站页面可见的责任者／朝代 |
| page_snapshot | 文本 | | 取证摘要（页面里证明归属的原文片段，≤200 字） |
| verdict | 枚举 | keep_one／keep_all／unknown | 判定 |
| keep_path | 文本 | 可空 | verdict=keep_one 时留下的记录 |
| drop_paths | 文本 | 可空 | 应删该 url 的记录 |
| verdict_by | 文本 | | 取证者／定夺者 |
| checked_by | 文本 | 可空 | 抽检者（独立） |
| note | 文本 | 可空 | |

输出（改库）：对 `drop_paths` 里的记录删去 `resources[]` 中该 url 的项；若该项是 `resource_groups` 某组的唯一成员，同删该组键；记录 `revision` 小版本 +1、`revised_at` 刷新、`ai_note` 记一行依据。不改其他字段。

## 三、程序架构
- `scripts/馆藏资源挂接/cuowa_fetch.py`（新写，Sol 用）：读清单，按站点限速 ≥2 秒／次取页面标题与责任者，写 `核对表.tsv` 的取证列。不判定。
- `scripts/馆藏资源挂接/cuowa_apply.py`（新写）：读已定夺的 `核对表.tsv`，对 `verdict=keep_one` 的行生成改库 diff（`--dry-run` 默认）。
- 复用：`health_check.py`（生成清单）、`.claude/qa/check_v2.py`／`check_schema.py`（校验）。运行在云端会话；改库在 book-index 分支。

## 五、测试数据与金标
- 试点 100 个 url 即金标来源；Selene 独立重判 30 行。分母＝已判定（非 unknown）行。
- 判据：原站页面标明的责任者／朝代与某一边的 `authors`／`dynasty` 相合 → 留该边；两边都不合或页面无责任者 → `unknown`。**不凭题名定夺**（题名两边相同）。
- 取证与库同源的风险：页面标题来自原站，不用库内字段。

## 七、风险与未决
- **最可能出错的一处**：把「两本都对」当错挂。例：同一 commons 文件确实是丛书合订，两个题名相同的作品都在里面。应对：`keep_all` 是合法结论；判不了记 `unknown`，不动。
- 站点云端可达性（commons、识典、维基文库未实测）：步 1 先验；不可达者交有浏览器权限的人，不凭题名定。
- 作者在库内被写成别名或异写（如徐彥純／徐彦純 同一人，作者「不相交」是假象）：步 3 定夺时先查异写；若是同一人，该 url 转「疑似重复 Work」线。
- 依赖：改库前须在排班.md 登记；写正式库每批 PR 须 Marlowe 批（评 ④）。
