# R1-E5：早稲田适配器＋罗马字剥离（引擎侧小设计，Everett，2026-10-15 洛杉矶）→ Milo 评审；与 Rowan（R3-3）对口径

## 一、先说结论（含“止”的判断）
- **不建议整体止，建议“小样验精度→再全量”**：早稲田 62,912 条里绝大多数是和书（大隈文書 13,864、西垣文庫 3,483、日本小说 3,124、俳谐…），与本仓中国古籍 Work 无关；但用粗原型（只做题名精确折叠命中，无责任者之外的任何规则）在**全量**上先量了一遍（机器几分钟，不是小样）：
  | 指标 | 数 |
  |---|---:|
  | 题名精确命中某 Work | 3,925 条（6.2%）／2,884 个顶层册（组） |
  | 命中且责任者相交（CJK 名折叠后） | 2,268 条／1,455 组 |
  | 其中唯一 Work＋责任者相交（≈确定档上限，未做朝代／丛书降级） | **1,723 条／1,026 组** |
  | 题名命中但早稲田无责任者 | 684 条（将落存疑 A_MISSING） |
  命中集中在汉籍类：哲学－经学 674／1,147、風陵文庫 457／1,685、雲英文庫 216、服部文庫 193、医学－古方 121、諸子 194／518、中国文学总记 142／496 等。
- 因此**确定档量级≈1,000 组（上限）**，不是“很低”，但需先验精度：大量命中是丛书子目（皇清經解、說郛：同一个 Work 下挂几百个子册）——这些按“顶层册＋每 Work≤3 藏本”收敛后实际写入数远小于 1,723 条。所以**真正值得做的写入量约数百组**，仍有价值；若 500 条小样精度＜95%，建议止在“只出存疑清单”。

## 三、适配器设计（`adapters/waseda.py`，沿用 naikaku 的 Record 接口，不动引擎主线）
1. **单位**：一组＝一个顶层册（`group_key = waseda-<顶层id>`，去掉 `_NNNN` 尾）；子册作为组内成员，题名取顶层册题名，子册只用来数册数。（与内閣“按册著录、按 file_id 成组”同构。）
2. **罗马字剥离**：NFKC → 取 ` / ` 左侧 → 去拉丁字母连续段（含长音符 āīūēō、撇号、连字符）→ 去 `[]※` → 取首个 `. `／` : ` 之前为题名主体；卷次段（`巻1-4`、`上,中,下`）与责任表述（`/` 右侧的 `著／撰／編／訳／画／校`）分离。无汉字则标 `T_EMPTY` → 无。
3. **责任者**：取 CJK 与假名 token，去生卒年与罗马字；两种形态各一个解析器；角色词（著／撰／編／画…）仅 著／撰／編／選／訳 计入主责任者，画／校／訂 不计（同内閣口径）。
4. **折叠**：jp=True（日文新字体表，已含 R1-A4 的 7 对）；不开内閣专用折叠，如需另议。
5. **tier 配置**：新 `waseda` profile＝naikaku profile（alias=True、shi_strip、segs），`engine.py --source waseda`。朝代：早稲田无朝代，责任者朝代从 `(生年-卒年)` 估不可靠，**不据此降级**；朝代冲突只在 Work 作者朝代与 version 年代明显早于作者时报 `ERA_VERSION_EARLIER`（沿 nlc 逻辑，需测）。
6. **丛书降级**：命中 Work 的 `COLLECTION`（皇清經解、說郛 等）→ 存疑；子目挂接另议。
7. **写入计划**：`make_item` 新增 waseda 分支（metadata 键 `waseda_id`＝顶层 id，待站点登记后定名）；每 Work≤3、取舍序同内閣（已挂占额→有影像→版本明确→册数→record_id）。

## 五、风险
1. **丛书子册**造成“命中很多、真写入很少”，数字不要当“可挂接 1,723”（见 §一）。
2. **同名异书**：和书里大量题名与汉籍同名（如 孟子、論語 的和刻本是对的；但“反挑眼”之类是别书）；靠责任者相交挡，无责任者的一律存疑。
3. **影像稀少**（90/62,912）：写入的 Resource 多半无在线影像，`types` 写法同 R3-1b 的 ooc 问题，需 Silas／A 块定；我不自定。
4. 字体表只有 80+7 字，和书异体（`経`＝經 已有，`冊/册`、`竝/並` 等）仍可能漏；E5-2 小样的“汉籍类无命中 100”就是量这个漏。
