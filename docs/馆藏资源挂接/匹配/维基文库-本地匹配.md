# 维基文库本地匹配方案

> 执行日期：2026-04-26  
> 脚本：[scripts/match_wikisource.py](../../../scripts/match_wikisource.py)  
> 数据存放：`D:\tmp\wikisource-multistream.xml.bz2`、`D:\tmp\wikisource-title-index.pkl`

## 问题背景

之前用 HTTP 单本搜索维基文库，慢、易触发限流、且无法做作者交叉校验。维基媒体提供完整 dump，可以本地化批量匹配。

## 方案

### 1. 数据下载（一次性）

```bash
# 索引文件 6.8 MB（标题→字节偏移）
curl -L -o /d/tmp/wikisource-index.txt.bz2 \
  https://dumps.wikimedia.org/zhwikisource/20260401/zhwikisource-20260401-pages-articles-multistream-index.txt.bz2

# 全文数据 2.5 GB（多流 bz2，可按偏移随机访问）
curl -L -o /d/tmp/wikisource-multistream.xml.bz2 \
  https://dumps.wikimedia.org/zhwikisource/20260401/zhwikisource-20260401-pages-articles-multistream.xml.bz2

# 标题列表 3.4 MB（用于书名匹配候选）
curl -L -o /d/tmp/wikisource-titles.gz \
  https://dumps.wikimedia.org/zhwikisource/20260401/zhwikisource-20260401-all-titles-in-ns0.gz
```

### 2. 索引格式

`pages-articles-multistream-index.txt.bz2` 解压后每行：
```
<字节偏移>:<页面ID>:<标题>
```
按字节偏移 seek + bz2 流式解压即可定位单个页面，无需解压全部 2.5 GB。

### 3. 匹配流程

1. **书名匹配**：规范化书名（去标点空格），与维基文库 205,508 个不重复书名对比
2. **作者校验**：对候选页面提取 `{{Header|author=...}}`，与 Work 的 authors 比对
3. **三级判定**：
   - `confirmed`（作者完全匹配）
   - `uncertain`（无作者字段 / 消歧义 / 重定向）
   - `rejected`（作者不符）

## 经验教训

### ✅ 有效的做法

1. **本地 dump 完胜在线请求**：单条匹配毫秒级，全量 3535 条 + 后续轮次 < 5 分钟
2. **多流 bz2 + 偏移索引**：按需解压单个流，2.5 GB 数据不必全解压
3. **作者交叉校验是关键**：纯书名匹配错误率 90%+，加作者后置信度大幅提升
4. **分级处理待核查项**：消歧义/重定向/无作者各有不同应对策略
5. **`book-index add-resource` CLI**：必须用，直接写 JSON 会绕过 index 同步（虽然实测发现似乎也会触发 index 更新，但仍应统一走 CLI）

### ⚠️ 踩坑

1. **bz2 流大小不固定**：初始用 `bz2.decompress(chunk)` 读固定 1 MB 失败，必须用 `BZ2Decompressor` 流式读到 `eof`
2. **Header 模板格式多变**：`{{Header|...}}`、`{{header | ... }}`、`noauthor=`、多 author 字段，正则要宽松
3. **CLI `--root` 参数容易理解错**：`--root` 指 `storage_root`，CLI 会自动派生 `<root>/book-index` 和 `<root>/book-index-draft`，所以 root 应填上一级目录 `D:/workspace`，不是 `D:/workspace/book-index-draft`
4. **`Reserved1` 错误**：如果 Work 已有同 id 资源，`add-resource` 会报 `Reserved1`（实际上数据已被正确写入），脚本应把它视为成功
5. **Windows + Python charmap 错误**：subprocess 调用时必须传 `PYTHONUTF8=1` 环境变量
6. **作者字符变体**：吕/呂、邱/丘、頥/頤 等字形差异需要在比较前归一化

## 复现方法

```bash
cd /d/workspace/overview
# 全量匹配（产出 wikisource_verified_full.tsv）
python3 scripts/match_wikisource.py --out wikisource_verified_full.tsv

# 只校验前 100 条（测试用）
python3 scripts/match_wikisource.py --sample 100
```

## 输入输出

- 输入：dump 三个文件（索引、全文、标题）
- 输出：`wikisource_verified_full.tsv`（verdict, work_id, work_title, work_authors, ws_title, ws_author, score, reason）
- 写入：通过 `book-index add-resource` 调用，写入 `Work/*/index.json` 的 `resources` 数组
