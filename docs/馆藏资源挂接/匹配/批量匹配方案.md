# 各数据源批量发现策略对比

> 调研日期：2026-04-26  
> 目标：对比四个文字资源平台是否有"批量目录数据"可用于一次性匹配，避免逐本搜索。

## 维基文库 ✅

| 项 | 值 |
|----|----|
| 是否有批量数据 | 有（Wikimedia dumps） |
| 入口 | https://dumps.wikimedia.org/zhwikisource/{date}/ |
| 关键文件 | `pages-articles-multistream.xml.bz2` (2.4 GB) + `multistream-index.txt.bz2` (6.8 MB) |
| 数据结构 | XML，每页含 `<title>` 和 `<text>`（wikitext） |
| 作者来源 | `{{Header|author=...}}` 模板 |
| 实测匹配率 | ~5500 / 64557 ≈ 8.5% |

**结论**：方案最完善，已完成。详见 [维基文库-本地匹配.md](维基文库-本地匹配.md)。

## Internet Archive ✅ 可批量

| 项 | 值 |
|----|----|
| 是否有批量数据 | 有（Scrape API） |
| 入口 | `https://archive.org/services/search/v1/scrape` |
| 关键参数 | `q=collection:chinesebooks`、`fields=title,creator,identifier,date`、`count=10000`、`cursor=...` |
| 候选 collection | `chinesebooks`、`chineserarebook`、`universallibrary` |
| 备选查询 | `q=language:chi AND mediatype:texts` |
| 数据量预估 | 数万到数十万条 |
| 拉取耗时 | 几小时（带游标分页）|

**结论**：方案成熟，优先级最高。详见 [internet-archive.md](internet-archive.md)。

## 识典古籍 ⚠️ 半公开

| 项 | 值 |
|----|----|
| 是否有批量数据 | 无 JSON API，但 sitemap 可枚举 |
| 入口 | `https://www.shidianguji.com/sitemap-book/{1..50}` |
| 数据结构 | HTML 页面，每页 200+ 链接 |
| 注意事项 | 外链经 `security.zijieapi.com` 包装，需解码 |
| 已上线书数 | ~3900+（项目目标 10000） |

**结论**：sitemap 可补全 fetch-shidianguji 工具的"发现"环节。详见 [识典-sitemap.md](识典-sitemap.md)。

## ctext.org ❌ 无目录 API

| 项 | 值 |
|----|----|
| 是否有批量数据 | 官方 API 无 listbooks，URN 设计上不可枚举 |
| 替代方案 1 | 爬分类页 HTML `https://ctext.org/{category}/zh` |
| 替代方案 2 | 借用 R 包 `ctextclassics` 内置的 `book_list` |
| 替代方案 3 | 用 `searchtexts` 按朝代分批查询 |
| 数据量 | 数千部 |

**结论**：与已有 CText 覆盖（5673条）重叠多，优先级低。详见 [ctext-补充.md](ctext-补充.md)。

## 总结

| 数据源 | 批量可行性 | 推荐方法 | 优先级 |
|--------|-----------|----------|--------|
| 维基文库 | ✅ 完善 | dump 本地索引 | 已做 |
| Internet Archive | ✅ 成熟 | Scrape API | ⭐ 高 |
| 识典 | ⚠️ 半公开 | sitemap HTML | ⭐ 中 |
| ctext | ❌ 不可枚举 | 分类页爬取 | 低 |
