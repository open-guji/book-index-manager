# 专名键表：名／别名 → entity_id 导出与增量规则（一页）

> GUJI-394（K1）｜执行：Edwin｜调用方：文本块（Mavis）｜脚本 `scripts/entity/export_keytable.py`｜样例 `键表样例/`（非人物全量＋人物前 300 条）
> **源 commit**：book-index `141d0d14c8`（样例与下列实测同源；调用方若用别的 commit 重导，以自己导出的 `键表.meta.json` 为准）。
> 全量实测：live 实体 37,838，键 68,101 行（键表约 4.3MB），歧义键 3,831，重定向 3,299（merged 611／promoted 2,683／retired 5）。

## 一、导出文件（均 UTF-8、TSV、LF、按 (key, entity_id) 排序，同输入逐字节可复现）
**键表.tsv**：`key, entity_id, primary_name, subtype, key_kind, dynasty, cand_n, norm_key, norm_cand_n`
- `key`：库内原字形的名字（`primary_name` 与 `alt_names[].name`）。
- `primary_name`：该 entity 的主名，方便调用方直接核对命中的是不是想要的那条。
- `subtype`：people／place／office／dynasty／reign／collective。
- `key_kind`：`primary` 或 `alt:<类型>`（字、號、異寫、…）。
- `dynasty`：**仅人物有意义**，其余 subtype 一律为空；供同名消歧。
- `cand_n`：同 subtype 内以**原字形** key 为名的 live entity 个数。**cand_n=1 可直接取用；>1 为同名歧义，调用方必须结合 dynasty／上下文消歧，不得取第一行。**
- `norm_key`：脚本内置异体折叠后的 key（NFKC＋逐字表：尙／尚、祕／秘、彞／彝、啓／啟、淸／清、郞／郎、爲／為、眞／真 等）。**不做繁简转换、不依赖 opencc**（保证输出可复现）；调用方的查询名过同一张表（表见脚本 `_VARIANTS`，`norm_key()`）后查 `norm_key` 列，即可宽松匹配异体。
- `norm_cand_n`：同 subtype 内同 `norm_key` 的不同 entity 个数，规则同 cand_n；异体宽松匹配命中时看它，不看 cand_n。

**重定向表.tsv**：`old_id, status, final_id, old_name`
- `merged`：墓碑（`merged_into`），`final_id` 已沿链解析到最终 live id。
- `promoted`：草稿晋升映射（`book-index/promotions/*.json` 中 type=entity 的条目：草稿 id → 正式 id），`final_id` 再沿 `merged_into` 解析，并**校验落在 live**；`old_name` 此类为空。文本里残留的**草稿 id** 一律经此表改指正式 id。当前 2,683 条全部落在 live。
- `promoted-dangling`：晋升目标已非 live（退役或不存在）。脚本照常出这行并在 meta `promoted_dangling` 计数，当前为 0；出现即需上报，不得静默取用。
- `retired`：退役（`retired:true`），无 `final_id`；这类 id 及其名**不入键表**，遇到即报缺。

**键表.meta.json**：`source_commit`（book-index 全 SHA）、`keytable_sha256`／`redirect_sha256`（两表文件内容指纹）、`script_sha256`（脚本内容指纹）、行数、`promoted_rows`／`promoted_dangling`。**调用方须记录并核对这些指纹**：拿到别处转来的键表，先算 sha256 对 meta，不一致即为非原版。

## 二、入表规则
- 只收 live 条目：无 `merged_into`、非 `retired`。墓碑条的名不入键（其别名应已并入存活条；未并入者不补）。
- 同一 entity 的多个名各占一行；脚本按 (key, entity_id, key_kind) 去重——同一 entity 若同名既作主名又作别名，会保留两行（kind 不同）。

## 三、增量规则
- **全量重导为准**：每次对 book-index main 某 commit 全量导出（秒级），不做就地补丁。
- **增量文件**：`export_keytable.py … --prev <旧键表.tsv>` 额外产出 `增量.tsv`（op=add／del／chg，键＝(key, entity_id)；chg＝key_kind、dynasty 或 **cand_n** 变化，列里带新值）。同名新增一个 entity 会使旧行的 cand_n 变化，因此也会出 chg——套用增量须连 chg 一起套。`norm_*` 两列不在增量里，**回挂（改写已挂好的 entity_id）一律以全量键表为准**。
- 增量只在 `meta.source_commit` 与手上旧表一致时才可套用，否则取全量。
- 触发：book-index 每次合入涉及 `Entity/` 或 `promotions/` 的 PR 后可重导；调用方也可随时自行重导（纯只读脚本，用法见脚本头注释，需给的是 **live book-index 仓**，因为 promotions 在那里）。
- **缺实体**不在键表内表达：查不到 key → 走缺实体需求入口（GUJI-395）。

## 四、调用建议（给文本块）
1. 先 key 精确匹配；无结果再用 `norm_key` 异体匹配；仍无再自行做繁简转换后重查。
2. 命中后若 `cand_n`（异体匹配时 `norm_cand_n`）>1，用 `dynasty`（及作品上下文）消歧；仍不能定者标「待判」，不要硬挂。
3. 命中旧 id／草稿 id 或需校验已有 `entity_id` 时，查重定向表（merged、promoted 都改指 final_id）。

## 五、已知局限
- **只含 Entity，不含 Work／Book 标题**；不含外部 id（CBDB 等）反查。
- 同名歧义 3,831 键（多为人物同名），键表只暴露、不裁决。
- 2026-10-15（GUJI-509 对 002/003 真实名单）异体表补 16 字：𠮓→變、𫎇→蒙、鈎→鉤、温→溫、巖→岩、璇→璿、錄→録、决→決、藴→蘊、沈→沉、畧→略、復→複、冲→沖、頴→穎、註→注、内→內。其中 沈→沉、復→複 会把同形不同义的字并到一起，只会让候选变多（norm_cand_n 变大），不会误取；`歴` 仍单向 歴→曆（歷代 类标题靠 bare／人工，暂不双向）。三份脚本（export_keytable／match_names／match_titles）的 `_VARIANTS` 须保持一致。
- 异体表是有限逐字表，不是完备归一；地名省文（如「某縣」省作「某」）、避讳字等需调用方另行处理，缺的写入缺实体入口。
