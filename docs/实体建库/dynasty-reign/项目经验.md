# 朝代年号完整录入（#580）项目经验

（Sasha，洛杉矶 10-13；块 D、验收抽检完成后再补一节。）

## 做对了的
- **先量现状再立项**：原题像"从零录入"，实测库已有 700+ 年号，于是改为"补缺＋对勘＋溯源＋帝王对照"，省掉大半录入工作。
- **分母先定稿**：块 A 把"≥2 独立来源一致的 586"定为硬分母，单源 495 逐条裁决不入分母，避免对勘数字被单源拉低或虚高。
- **裁决账只增不减、有脚本校验**（`verdict_check.py`）：reject／adopt 须 ≥2 条独立来源链，否则记 open，数据不动；范围外 reject 须带 out-of-scope。账 1160 行 0 error。
- **相邻朝代年差 ≤1 视为口径差，不归一**；前涼等沿用他朝年号不记为自己的年号；非全国性政权 period 保持 null。
- **史载例外走白名单**（`check_v2_allow.txt` 逐条带理由），不为清零去改对的数据。
- **块 D 给 Haiku 的护栏**：sources 的书名必须落在裁决账该实体的 `book:` 来源内（`d_check.py`）；不得升 reviewed；每 PR ≤10 文件。

## 踩过的坑
- 外部站限流（zhwp 429）、云端证书问题：来源改用 DILA＋已缓存源表。
- 子串匹配把《新元史》当成《元史》：书名匹配须带《》边界。
- git 对非 ASCII 路径加引号，`git diff --name-only` 须用 `-z`。
- 单链来源（只有一个独立链）不够 reject，38 行须降为 open。
- 无账可依时让 Haiku 补 sources 有编造出处风险：宁缺勿编，写"库内原有，未经本期复核"。
- 会话压缩后别凭印象，读 `计划/` 与 `裁决/` 文件接手。
