## 一、本块目标与边界
目标：把块 B 差异清单里每条差异逐条裁决（采纳／不采纳／存疑），把采纳项写成草稿库 dynasty／reign 条目的 PR，同时把理由记进裁决账；并处理 Sienna 交接的接手项（漢×5、蜀／閩／新羅、承平／鳳凰）。
不做：不改 schema；不建人物条；不补 `description.sources`／`dates.basis`（块 D）；不设 `review.status = reviewed`（须非原作者抽检，见第四节步 6）；不发布上线；不碰域外年号、民国。不凭记忆裁决：每条采纳须有 ≥2 个独立来源（见块 A 可信度表），仅 1 个来源者标「存疑」，不入 PR。
交付物（放 `项目进展/朝代年号录入/裁决/`，不进数据仓）：`verdicts.jsonl`（裁决账）、`接手项处置.md`、`C1／C2／C3 PR 清单.md`；数据仓侧为草稿库 PR。

## 二、数据格式
**裁决账 `verdicts.jsonl`**（每行一条 JSON）：
| 字段 | 含义 | 可空 |
|---|---|---|
| `diff_id` | 差异清单行号／键，对应块 B 前五列契约 | 否 |
| `verdict` | `adopt`／`reject`／`open` | 否 |
| `rule` | 依据的规则编号（如 R-范围、R-两源、R-史载例外） | 否 |
| `sources` | 参照的源（块 A 源内键）≥2 个；`open` 时可为 1 个 | 否 |
| `action` | 拟对草稿库做的操作（新建 reign／改 dates／加别名／加白名单） | 是 |
| `entity_ids` | 涉及条目 id（正式库 12 位 id；草稿 13 位 id 同时记 `promoted_to`） | 是 |
| `note` | 一句话理由 | 是 |
裁决规则（写入 `接手项处置.md` 头部，之后不得凭印象改）：R-两源＝至少两个独立来源一致才 adopt；R-史载例外＝正史／通鉴明载但与朝代区间不合者，不改数据、加 `check_v2_allow.txt` 登记；R-范围＝域外、民国、边疆未入分母者 reject 并写 `out-of-scope`。

## 三、程序架构
- 无新程序。用块 B 的 `差异清单.tsv`＋`guji_norm.py`；新增 `scripts/make_entities.py`（把 adopt 行转成 Entity JSON，沿用 `给S-字段清单.md` 的冻结字段，id 用库内既有生成器）和 `scripts/verdict_check.py`（校验裁决账：必填字段、sources≥2、adopt 行必有 action）。
