## 一、本块目标与边界
目标：把库内 734 条年号（及 139 条朝代）与块 A 的各源表做**可复跑、可解释**的逐条比对，输出五类差异清单，交 Sasha（块 C）逐条裁决。
不做：不裁决（不改任何库内值，`建议` 列只是提示）；不改 schema；不写 book-index／book-index-draft（本块全程只读，因此不涉及排班登记）；不抽取外部来源（归 A）；不搬运外部描述文字；不碰帝王人物（归 E）；键表归块 F。
交付物：`scripts/guji_norm.py`（归一）、`scripts/entity_audit.py`（扩展）、`scripts/recon_reign.py`（对勘）、`政权映射.tsv`、`差异清单.tsv`、`scripts/tests/`（金标用例）、`scripts/README.md`。

## 二、Schema／数据格式
### 2.1 输入
- **库内**：`--root <book-index 或 book-index-draft 工作树>`，遍历 `Entity/**/*.json`，取 `subtype=dynasty|reign`；跳过带 `_promoted_to`／`promoted_to` 的草稿旧稿（与 `gen_dynasty_reign_keys.py` 同口径）。读的字段：`id, primary_name, alt_names[].name/type, dynasty_id, ruler.name, dates.start/end, parent_id`。
- **源表**：块 A 契约，TSV UTF-8，`#` 开头行忽略，首个非 `#` 行为表头：`来源｜源内键｜年号｜朝代(源写法)｜帝王(源写法)｜起｜止｜备注`。起止空 = 未知，**不当 0 也不报分歧，另记"源缺值"**。
- **政权映射表** `政权映射.tsv`（B 产出，Sasha 复核）：`来源｜朝代(源写法)｜库内 dynasty_id｜库内 primary_name｜状态`，状态 ∈ `auto｜confirmed｜边疆｜无对应`。样例：`zhwp-中国年号列表	唐朝	hixi1ub…	唐	auto`；`zhwp-中国年号列表	孫吳	…	三國吳	confirmed`；`zhwp-中国年号列表	南詔及大理	（空）	（空）	边疆`。多个库内政权对应一个源写法时（如源「梁」＝南朝梁／後梁，源「宋」＝南朝宋／北宋…）一律写成多行，匹配时靠起年消歧。

### 2.2 输出：`差异清单.tsv`（契约：块 C 消费）
列：`类别｜库内 id｜库内值｜各源值｜建议`，UTF-8，首行 `#` 注释写库指纹（`git rev-parse --short HEAD`）、各源表文件的 sha256 前 8 位、脚本 commit、运行时刻（洛杉矶）。**为方便裁决另加两列放在最后，不破坏前五列顺序**：`序号`（稳定行号，按类别＋库内 id＋年号排序后编，复跑不变）、`严重度`（`高｜中｜低`）。
| 类别 | 判定 | 库内 id | 库内值 | 各源值 | 建议（只是提示） |
|---|---|---|---|---|---|
| 缺条 | 源表某行在库内找不到对应（"源有库无"，库内 id 空）；或库内某条在**所有**源表都无对应（"库有源无"，各源值空） | 库有源无时填 | 库有源无时：`年号｜朝代｜起-止` | 源有库无时：`来源:年号｜朝代(源)→映射｜起-止` 多源分号隔开 | 源有库无且多源一致→"疑缺，查是否属边疆政权／争议年号"；库有源无→"查异体或库内误条" |
| 起讫分歧 | 已匹配，且至少一个源的 起 或 止 与库内不等（两端都有值才比） | id | `起-止` | `来源:起-止` 逐源 | 见 3.4 的强度规则 |
| 归属 | 已匹配（名字＋起年±2 吻合），但源的政权映射 ≠ 库内 `dynasty_id`，或源帝王与库内 `ruler.name` 归一后不等 | id | `朝代｜ruler.name` | 各源 `朝代→映射｜帝王` | 帝王口径问题标"转块 E"，政权问题标"块 C" |
| 异体 | 已匹配，但库内 `primary_name` 与源写法**归一前**不同（简繁、异体字、避讳字），或只能经 `alt_names` 对上 | id | `primary_name` + 全部 alt_names | 各源写法 | 若库内无此写法的 alt_names → "建议补别名 type=異體"；若源是库的简体 → 仅信息，低 |
| 重名 | 同一归一名在库内有 ≥2 条，或在某源表有 ≥2 行；且两边条数不等或无法一一配对 | 各 id 分号隔开 | 各条 `朝代｜起-止` | 各源行 `朝代｜起-止` | 说明哪几条能配、哪几条悬空 |

**严重度规则（确定性，写进代码）**：高＝起讫分歧中 ≥2 个独立来源的值彼此一致而与库内不同，或缺条中 ≥2 源都有；中＝单源分歧或单源缺条；低＝仅异体信息、起差为 1 且 ≥1 源与库一致。

### 2.3 输出：辅助文件（不入数据仓）
- `对勘报告.md`：计数表（见 §五）、各类别数、未映射政权清单、金标结果。
- `匹配明细.tsv`（调试用）：每个源行→库内 id 的配对、配对依据（名字/起年/政权/帝王各得分）。差异清单是它的子集视图，**每行差异必须能在明细里找到依据**。

入口：`python3 scripts/recon_reign.py --root <库> --sources 源表/ --map 政权映射.tsv --out <目录> [--draft-root …] [--seed 20261012]`；`python3 scripts/entity_audit.py <库根> [--json]` 保持旧用法（位置参数、原样输出）不破。运行在云端会话，纯标准库＋`opencc-python-reimplemented`（pip，已验可装）。

**复用**：库载入与遍历逻辑沿用 `entity_audit.py`／`gen_dynasty_reign_keys.py` 的写法（`promoted_to` 跳过、`NORMALIZE` 逐字映射表）；不重造。`ruler_probe.py` 的 (帝王,朝代) 统计并入 `entity_audit.py --json` 的 `rulers` 节，原脚本保留不删。

### 3.1 归一（`guji_norm.py`）——本块最易出错处，单列
实测：维基源表为简繁混排，直接比字面，库内 552 个不同年号名里只有 405 个与源表字面相同；经 `s2t` 后 547／552 能对上。**但 opencc 会过转换**（如"咸豐"被转成"鹹豐"、本不该动的字被动），所以规则是：
1. 两边（库、源）**同一函数**归一，用归一值作匹配键，原值保留用于报告和"异体"判定。
2. 归一 = `NORMALIZE` 逐字表（沿用键表的 6 字，**块 A 与 F 共用同一份**）→ opencc `s2t` → **例外表**回改（写在 `guji_norm.py` 顶部的常量，如 咸/鹹、乾/幹类，每条带注释说明为什么）。例外表初版由实测差集生成：库内只在库、源内只在源的 5 个名字（太平天國、永憙、紹武、鹹豐、龍啟）人工看过再定。
3. 不做的：不把"歴↔曆"以外的历史异体自动合并（如 憙/熹），除非例外表显式列出；未归并的会落入"缺条"并带"疑异体"提示，由 C 裁决。
4. `norm_ruler`：去前缀庙号／谥号字样如"汉武帝 劉徹""趙秦王 刘曜"→取末尾 2–4 字人名并归一；氏族前缀（愛新覺羅、孛兒只斤）按已知清单去除后比。比对失败不判错，标"帝王待块 E"。
5. `norm_dynasty`：只做 去"朝"尾、归一繁简；真正的源→库映射走 `政权映射.tsv`，不靠字符串猜。

### 3.2 匹配算法（`recon_reign.py`，确定性）
1. 库内年号按归一名建索引（含 `alt_names`，除 type=全稱）。源行按归一名取候选；无候选→待"缺条"（再查是否异体：编辑距离 1 的同年同政权候选只作提示，不自动配）。
2. 源行→政权映射（多行时多个候选政权）。对每个（源行,库候选）打分：政权相符 +3，起年相等 +3、差 1 +2、差 ≤2 +1，帝王归一后相符 +2。**只有政权相符或起年差 ≤2 才算候选**，其余不配。
3. 同一归一名下做**一对一最优配对**（条数极少，最多十几条，枚举或匈牙利，平局按库内 id 升序，保证复跑不变）；剩余未配的库内条或源行进"缺条"，条数不等的名字同时进"重名"。
4. 以"源"为单位聚合：同一库内条被多个源配到，各源值并排写进差异行。

### 3.3 库内体检扩展（`entity_audit.py`）
旧输出不动。新增（皆为只读）：`--json` 结构化；`reign.description.sources` 非空计数改为按"条"列表输出（实测 0／873 与旧脚本"2"对不上，见 §七）；朝代年号区间外 ±5 的 4 条用 R1 同口径（`check_v2` 的 R1 规则源码为准，**实现前先读 `.claude/qa/check_v2.py` 的 R1，不手写另一套**）。

### 3.4 起讫分歧的强度（供"建议"列）
起年差 1：常因"改元当年记起年"与"次年起"之别，提示"查是否口径差"；差 ≥2：提示"查是否另一年号或抄误"；止年缺或库内 `end` 与下一年号起年冲突，只提示不判错。

## 七、风险与未决
- **最可能出错的一处**：归一过转换或不足，使"异体"被当成"缺条"（或相反），整批差异清单看似很多、实为假差异。对策：例外表人工看过；步 1 的验收数字（547／552）是硬门槛；清单里每个"缺条"带"疑异体"提示。
- 同一政权名在源里歧义（"梁""宋""齐""楚"）：靠映射表多行＋起年消歧；消歧不了的进"重名"，不猜。
- **数字对不上的两处，需要在执行时先弄清**：①总计划写 `description.sources` 非空 0／873，我实测 `entity_audit.py` 输出 reign 为 2（未核朝代）；步 3 先复核这 2 条是什么再报，不改总计划数字，只在评论里指出；②总计划"重名年号 552 个不同名中 109 个重名"，口径是 `primary_name` 字面重名，归一后可能更多，步 5 报两种口径。
- 草稿库旧稿与正式库并存：本块默认只读**正式库**；`--draft-root` 只用于核对一致性，不进差异清单（避免同一条计两次）。
- 依赖块 A 的政权范围口径（边疆政权是否进分母）还未定；本块的处理是"边疆"状态单列，口径定了只改映射表状态，不改代码。
- 未决（默认值照做，不阻塞）：差异清单是否按严重度分批交 C——默认分批（先"高"）。
- 若 opencc 在某环境装不上：退路是只用 `NORMALIZE` 逐字表＋例外表，覆盖变差，步 1 验收数字需下调，会如实报告。
