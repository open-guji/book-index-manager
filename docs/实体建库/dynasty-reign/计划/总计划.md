# 项目总计划：朝代年号完整录入

> 项目主力（总设计）：Sasha（文献学者，账号 B 实体）　｜　经理：Mirren　｜　立项：2026-10-12（洛杉矶）　｜　状态：设计中（待 Mirren 批范围）
> 项目计划卡：open-guji-core/overview#580　｜　标签：`项目:朝代年号录入`　｜　计划文件目录：`项目进展/朝代年号录入/计划/`

## 一、目标（一句话＋为什么）
让朝代、年号（含帝王本名／庙号／谥号与年号的纪年对照）的 Entity 数据**完整、每条可溯源、经两个以上独立来源对勘**，并能被文本侧「专名识别与链接」稳定回挂（#574）。为什么：现有 873 条是 10-07 批量入库的，全部 `unreviewed`、没有一条写出处，无法回答「凭什么这么写」，与项目「每条成果标注来源、可被追问」的承诺不符；缺口大小也还没有分母。

**一个重要事实先说**：用户 10-12 说「实体团队可能已有零星在做」——实测远不止零星。朝代 139、年号 734 早已在 10-07 经 P2a／P2b／P2c 入草稿库、P4 升格进正式库（见第三节）。所以本项目的主体不是「从零录入」，而是**补缺 → 对勘 → 补出处 → 帝王对照 → 接回挂**。

## 二、不做什么（先写）
- 不改 schema（S0 冻结）：不新增字段、不新增 `alt_names.type`；`external_ids` 只许 `wikidata_id` 且第一期不填；**不存任何 `cbdb_*`／DILA／CHGIS id**（overview#464 用户定）。
- 不搬运外部库的描述性文字、不整表搬运；外部库只作对勘参照，条目内容全部自写（CC0）。
- 不建人物条目（帝王的 people 条归 Soren／P5，本项目只提需求单、等其交付后回填 `ruler.entity_id`）；不碰地名、官署（Sienna P6 只留这两类）；不碰 Work／Book；不碰整理本 span↔entity 匹配与回挂（归文本团队 P7）。
- 不发布上线（发布只由网站经理做）；升格走 `promote-work` 同款流程，由经理审合。
- 民国纪年（民國、洪憲）、日本／朝鮮／越南／琉球年号**不在本期验收内**（块 E 可选，见第四节；待用户定，不答则不做）。

## 五、总体架构与共用契约
数据流：
```
外部来源（DILA／维基类纪年表／CBDB 年号表／纪年表类公开数据，只读）
   → 块 A 统一抽取 → 源表 TSV（本仓外，overview 暂存，不进数据仓）
   → 块 B 与库内 873 条比对 → 差异清单.tsv
   → 块 C 逐条裁决 → 草稿库 PR（Entity/ 下 dynasty／reign 文件）＋裁决账
   → 块 D 补 sources／basis／review → 同一 PR 的后续提交
   → 升格（promote 流程，经理审合）→ 正式库 → build 产出键表（块 F）→ 文本侧回挂（#574）
   块 E：帝王对照表 → 反馈 ruler.name 口径给 C；需求单给 Soren → 人物条交付后回填 ruler.entity_id
```
契约（全部沿用冻结 schema，来源 `schema/entity/dynasty.md`、`reign.md`、overview 专名建档 `给S-字段清单.md`）：
| 接口 | 谁产出 | 谁消费 | 格式 |
|---|---|---|---|
| 源表 | A | B、E | TSV，UTF-8，列：`来源｜源内键｜年号｜朝代(源写法)｜帝王(源写法)｜起｜止｜备注`；每行带来源 URL 与取数时刻 |
| 差异清单 | B | C | TSV，列：`类别｜库内 id｜库内值｜各源值｜建议`，五类同上 |
| 裁决账 | C | D、审核 | `verdicts.jsonl`，verdict=open，rule 必填；规则写成可复核的句子（如「≥2 源起年一致采之；冲突标 disputed」） |
| 条目 JSON | C、D | 数据仓 | 字段只用 dynasty／reign 现有集合；`dates.start/end` 整数、公元前负数、无 0 年；改元当年记起年；同名年号各自一条，消歧靠 `dynasty_id＋ruler＋起年` |
| 帝王对照表 | E | C（口径）、F、Soren（需求） | TSV，列：`本名｜庙号｜谥号｜朝代｜在位起止｜年号序列`，每行带来源 |
| 键表 | F（实现归 build F6-5b） | 文本侧 P7 | `_build/dynasty_reign_keys.json`，格式见 `专名建档/P4-升格/dynasty_reign_keys-交接.md` |

## 六、项目验收标准（每条一个命令或数字；对勘类数字的分母已由块 A 定稿（586，见 `分母.md`））
1. **门槛**：book-index 与 book-index-draft 上 `check_v2 --summary` ERROR 0、R1／D2／D3 的 WARN 与 INFO 均 0（当前 WARN 2、INFO 7）；`verify.py --strict` 五项全 0；索引漂移 0；`promotions` 校验通过。
2. **覆盖**：中国年号对「分母」（块 A 定稿：≥2 个独立来源并集去重后的年号数）覆盖 ≥ 99%；其余缺条逐条在 `缺条说明.md` 写明理由（学界异说／争议政权／本期不收），未处置 0。分母数字（块 A 定稿 10-12）：**两源（维基＋DILA）一致的 586 个年号**为硬分母（口径见 `分母.md`）；单源 495 个（维基独有 440、DILA 独有 55）逐条裁决，不入硬分母；边疆政权、日韩、民国、空起年存疑项不入。
3. **对勘**：库内每条的起讫年与 ≥2 个独立来源一致的占比 ≥ 98%；其余全部在 `basis` 写明裁决依据并标 `review.status=disputed` 或 `unreviewed`，不得是笼统一句。
4. **溯源**：`description.sources` 非空条数／总条数 = 100%；`dates.basis` 不含笼统句「與CBDB、DILA相符」（`grep` 为 0）。
5. **抽检**：分层随机抽 100 条（朝代 20、年号 80，按朝代层化，种子写进报告），由非原作者（实习生以外的学者／Mirren）独立核对，错 ≤ 2 条；错出的类型全部回溯到同类条目并清。
6. **帝王**：`ruler.name` 口径统一（`grep` 氏族前缀为 0，或例外逐条列表）；`帝王年号对照.tsv` 行数 = 年号条涉及的（帝王，朝代）对数；`ruler.entity_id` 回填率 = Soren 已交付的帝王人物条覆盖部分，未覆盖者在 `遗留.md` 逐条列出并开卡给 Soren。
7. **回挂**：键表重生成，键冲突检查（同键多候选的 `ambiguous` 标注）与 `dynasty_reign_keys-交接.md` 一致；#574 命中统计里朝代／年号「new_candidate」在 vol02／03 样本上清零或有去向。
8. **清理**：临时脚本、源表、中间文件要么入 `scripts/` 并有 README，要么删除；无 `在跑` 的项目内 issue；经验写回 `项目经验.md`。
