# 朝代年号录入 脚本（块 B）

| 脚本 | 作用 |
|---|---|
| `guji_norm.py` | 归一函数（norm_name／norm_dynasty／norm_ruler／parse_year）；块 A、F 共用。需 `pip install opencc-python-reimplemented` |
| `entity_audit.py <库根> [--json]` | 库内体检；无 `--json` 输出与旧版逐字相同 |
| `build_dynasty_map.py` | 生成 `../政权映射.tsv`（人写小字典＋校验库内政权名存在） |
| `recon_reign.py` | 对勘主程序，只读库 |
| `tests/test_norm.py`、`tests/run_tests.py` | 归一与对勘的金标测试（`--break` 故意改错应变红） |

复现：
```
python3 recon_reign.py --root <book-index 工作树> --sources ../源表 --map ../政权映射.tsv --out ../对勘产出 --check-conservation
```
输出：`差异清单.tsv`（前五列 = 总计划 §五契约，末尾 序号／严重度）、`匹配明细.tsv`、`对勘报告.md`。守恒不成立退出码 2；同输入复跑，两个 TSV 逐字节相同（运行时刻只在报告里）。

已知局限：①单源对勘，严重度“高”需 ≥2 源；②边疆政权（映射状态“边疆”）的缺条一律低；③帝王比对只做归一后字符串相等，“元宏／拓跋宏”这类改姓写法会进“归属·转块 E”；④匹配为每名字组内按得分贪心配对（得分相同按库 id 升序）。

## 第二源 DILA 与「单源待裁」（2026-10-12）
- `源表/` 下放多个 TSV 即多源；DILA 表无表头，`prep_dila` 预处理：跳日韩／民国／无年号行，朝代名去方括号别称（`北魏[元魏;後魏]`→北魏），按帝王切分的同名同朝连续行并成一条（`仁宗→英宗`）。DILA 朝代名映射在 `build_dynasty_map.py` 的 `MAP_DILA`（来源 `dila-time`）。
- 缺条按（归一名, 朝代）聚簇（跨源起年差 ≤1 视为同一条）：≥2 源 → 缺条/高；仅 1 源 → **单源待裁**/中；边疆 → 缺条/低。
- 起讫分歧新增口径识别：只有止年比库多 1（源把改元当年算进本年号）→ 低，标「系统性口径差，非库错」，避免淹没真分歧。
- 分母覆盖：`denominator_coverage.py` 用同一匹配规则核对 `分母产出/分母-两源一致.tsv`，输出 `对勘产出/分母覆盖-两源一致.tsv`。
